# 数据存储与升级

重新发行的 v1.3.0 已删除防篡改机制。配置和账号直接读写普通 JSON，不签名、不创建可信快照、不进行自动恢复，也不需要安全初始化。

## 配置与账号

源码默认数据目录为 `server/`，Linux 独立程序默认是程序旁的 `data/`，可以用 `LANTALK_DATA_DIR` 指向其他目录。

- `config.json`：监听端口、上传限制、极域和超管 IP 配置，停服修改后重启读取。
- `users.json`：账号 ID、用户名、带盐 scrypt 密码哈希、角色、IP、Bot 凭据和会话，启动读取，合法接口操作会保存。
- 服务不监控这些文件；手改账号不会被还原，重启后读取编辑结果。面板操作可以同步其他业务数据，因此日常修改优先使用面板。
- 全新数据创建唯一初始超管；已有账号格式必须恰好一名 `superadmin`。错误或缺失的既有账号数据会报错，不默认重建或自动提升用户。

## 超级管理员 IP

`config.json` 的 `superadminIP` 指定超管设备 IP。留空时保留已绑定 IP，尚未绑定则首次成功密码登录绑定。更换指定 IP 会撤销旧会话，保留 ID 和密码；与其他账号冲突会拒绝启动。固定后，面板／API 不允许覆盖或解绑，应改 JSON 重启。

清空字段不会自动解除已有绑定。希望再次首次登录绑定时，清空配置并重启，再通过管理面板解绑。

## 从原 v1.3.0 或旧 exe 迁移

1. 停止旧服务，备份完整数据目录，保留账号、群组、好友、消息、文件、头像和个人设置。
2. 更新源码或 Linux 程序。Windows 不再提供 exe，改用 Node.js 22+ 启动源码。
3. 保持原数据路径，或用 `LANTALK_DATA_DIR` 指向原 `data/`。程序直接读取现有 `users.json`，不读取旧密钥、可信状态或 `.security-initialized` 标记，无需初始化。
4. 验证数据与账号后，旧私有目录及标记可自行归档或清理；新程序不会主动删除历史文件。如果仍需回退旧版，应保留旧版完整备份，包括它依赖的旧私有文件。
5. 根据新设备地址调整 `superadminIP`，避免与普通用户冲突，重启并登录验证。

如果账号副本已缺失或损坏，请从自己的备份恢复 `users.json`；新版本不提供从旧快照自动恢复的路径。很早旧版只有 `admin` 时，停服备份并确认初始管理员，将且仅将该账号设为 `superadmin`，程序不会自动选取。

旧安全目录相关环境变量不再生效。数据文件包含凭据哈希、会话与消息，应由服务器部署者限制访问。
