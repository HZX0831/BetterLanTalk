# 配置与账号的可信存储

本版本保护 `config.json` 和 `users.json`。普通 JSON 文件是兼容副本；程序只使用私有目录中经过 HMAC-SHA256 校验的可信状态。保护内容包括服务器配置、账号 ID、密码哈希、全站角色、IP 绑定、Bot 令牌哈希、登录会话及唯一超级管理员 ID。

## 首次安装和升级

全新、空的数据目录可以正常启动，自动创建唯一初始超级管理员。超管仍在首次成功密码登录时绑定 IP。

已有数据必须先停止旧程序，备份完整数据目录，确认现有账号中恰好一名 `superadmin`，再进行一次显式初始化：

```bash
# 源码运行，在仓库根目录执行
node server/server.js --init-security

# Linux 独立程序
./BetterLanTalk-linux-x64 --init-security
```

Windows 在 exe 所在目录打开终端，执行：

```powershell
.\BetterLanTalk-win-x64.exe --init-security
```

初始化成功后服务正常运行，以后直接启动即可。零个或多个超管、账号文件缺失、配置无效时，初始化会中止，不自动提升或降权。原有超管 ID、密码和已绑定 IP 保留。初始化只能信任当时确认正确的数据，不能推断此前被修改的原值。

## 私有目录

启动日志会显示实际私有保护目录。默认位置为：

- Windows：`%LOCALAPPDATA%\BetterLanTalk\security\<数据目录路径摘要>`。
- Linux：`${XDG_STATE_HOME:-~/.local/state}/BetterLanTalk/security/<数据目录路径摘要>`。

也可用 `LANTALK_SECURITY_DIR` 指定一个位于数据目录之外的专用路径。首次建立基线前该路径不应存在；不要把密钥放进数据目录、源码仓库、公共共享目录或上传目录。

Linux 目录权限为 `0700`，文件为 `0600`；Windows 使用受保护 ACL，只授予当前服务账号和 SYSTEM。Windows 使用系统自带 Windows PowerShell 设置 ACL，无需联网或另装 Node.js。一个私有目录同时只允许一个服务实例运行；异常退出留下的锁会在确认原进程已退出后清理。

## 自动恢复与正常修改

配置修改通过管理面板或有权限的配置 API 完成。注册、密码、角色、IP、会话和 Bot 凭据修改沿用现有功能。服务先将合法修改原子保存到可信状态，再更新普通 JSON 副本；成功保存的最新状态成为新的恢复基准。

启动时、保存前和运行期间每两秒检查普通副本。直接修改、删除、写坏 JSON 或替换为旧文件，都会恢复到最新可信状态。运行中的鉴权不会读取被修改的副本；恢复日志只记录文件名和版本，不输出凭据。

超级管理员由固定 ID 唯一指定，改名不影响身份。服务不会因为缺少超管而提升其他账号，也不能通过接口创建第二个超管。

密钥或可信状态缺失、变化、校验失败，或无法可靠保存时，服务会停止。`--init-security` 不能覆盖已启用保护的部署，也不会重新生成默认账号。

## 备份、换机和恢复

1. 停止服务，备份整个数据目录和对应私有保护目录，限制备份的读取权限。私有目录包含 `key`、`state.json`；保留数据目录中的 `.security-initialized` 标记。
2. 升级替换 exe，保持数据目录路径和运行账号时，继续使用原私有目录。
3. 换机、换运行账号或移动数据目录时，恢复两份备份，用 `LANTALK_DATA_DIR` 和 `LANTALK_SECURITY_DIR` 指向对应位置。程序会重新收紧私有目录的访问权限。
4. 恢复损坏数据时，停止服务并恢复两份匹配的可信备份，再正常启动。不要删除安全标记或使用初始化参数绕过故障。

防护对象是只能修改普通数据文件、不能修改程序与私有保护目录的人。拥有服务器操作系统及程序完整控制权的人仍可绕过本地防护。本轮保护范围不包括消息、群组和好友关系等其他数据文件。
